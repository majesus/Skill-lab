Dos rutas para probar la skill.

Una skill es una carpeta de instrucciones que Claude puede usar cuando una tarea encaja (la diapositiva siguiente lo explica). Para probar una skill existen dos rutas, según lo que permita la cuenta de cada participante.

Qué cambia entre A y B

Los pasos 1 a 8 son idénticos. Cambian el paso 9 (instalar o pegar) y lo que se puede afirmar en los pasos 10 a 13: con la ruta A, que Claude activó la skill; con la ruta B, solo que las instrucciones producen lo esperado.

Cómo comprobar si la cuenta admite skills
  1. Abrir Claude en el navegador o en la aplicación de escritorio.
  2. Buscar Customize › Skills: si aparece, la cuenta puede usar skills.
  3. Revisar en Settings › Capabilities el ajuste «Code execution and file creation»: las skills propias lo necesitan. En Team y Enterprise lo activa el propietario de la organización, no el usuario.

Esto describe Claude en la web y en el escritorio; en Claude Code no se aplica.

Fuente: Centro de ayuda · Using Skills in Claude.

Idea clave. «Da igual la ruta: todos hacemos el mismo recorrido. Solo cambia el paso 9 y lo que podemos afirmar al probar.» Que cada persona pulse su ruta ahora: quien lo descubra tarde tendrá que cambiar en pleno trabajo.

Honestidad. En la ruta B no se puede afirmar que la skill «se activa», solo que sus instrucciones producen el comportamiento esperado. Que lo anoten así.

Concepto

Una skill es una guía de trabajo que Claude consulta cuando la necesita.

Qué es

Una carpeta con instrucciones

Como mínimo, un archivo llamado SKILL.md que explica una tarea: cuándo se usa, qué necesita, qué hace y qué entrega.

Cómo funciona

Claude decide cuándo usarla

Claude conoce siempre el nombre y la descripción de tus skills. Si tu petición encaja, decide cargarla, lee las instrucciones completas y las aplica. No siempre acierta, y también se puede pedir por su nombre.

Para qué sirve

Tareas que se repiten

No repites en cada chat el formato, los pasos ni los límites: quedan guardados con el mismo criterio.

Ya se usan skills sin advertirlo

Cuando se pide a Claude un documento de Word, una hoja de Excel, una presentación de PowerPoint o un PDF, Claude emplea skills que ya trae incluidas. Una skill propia funciona igual, pero para una tarea propia: por ejemplo, leer una tabla de indicadores bibliométricos.

Una analogía

Una carpeta de procedimientos que se deja a un ayudante nuevo. Cada procedimiento lleva una etiqueta con su título y una línea que dice para qué sirve: son el nombre y la descripción, siempre a la vista. Cuando llega una tarea, abre solo el procedimiento cuya etiqueta encaja y lo sigue: es el SKILL.md. Los anexos (plantillas, ejemplos) los consulta solo si el procedimiento lo indica. Y se le puede indicar: «usa el de indicadores».

Concepto · uso automático y control

¿Quién decide cuándo se usa una skill?

PreguntaRespuesta según la documentación oficial
¿Puede Claude decidir por sí solo usar una skill?Sí: es su comportamiento normal. Si tu petición encaja con la descripción de una skill disponible, puede cargarla sin que la nombres. Es un juicio del modelo, no una regla determinista: puede no usarla aunque encaje, o usarla cuando no procede.
¿En qué se basa? ¿Influyen el nombre y la descripción?Antes de usarla solo conoce, de cada skill, el nombre y la descripción (unos 100 «tokens» por skill). La descripción es el factor decisivo; el nombre ayuda a identificarla.
¿Lee siempre el contenido completo?No. Solo si decide usarla carga el cuerpo de SKILL.md; los archivos adicionales, solo si las instrucciones lo piden; y de un script solo entra en la conversación lo que este devuelve al ejecutarse.
¿Se puede hacer que se use solo ante cierta petición, expresión o condición?Sí, pero de forma orientativa: se escribe en la description (frases reales de petición y cuándo no usarla). En Claude Code, el campo paths limita la carga automática a archivos que coincidan con unos patrones. Ninguna de las dos formas garantiza el resultado: se comprueba probando.
¿Hay una forma documentada de bloquear o controlar el uso automático?En Claude.ai: cada skill tiene un interruptor (una skill desactivada no está disponible para Claude) y puedes pedirla por su nombre. En Claude Code: disable-model-invocation: true (solo la invocas tú, con /nombre, y su descripción deja de estar en el contexto), user-invocable: false (solo Claude) y reglas de permisos sobre Skill.
¿Puede indicarse que solo se use cuando yo la invoque expresamente?En Claude Code, sí: disable-model-invocation: true. En Claude.ai no consta un equivalente exacto: lo más cercano es mantenerla desactivada y activarla cuando la necesites, o redactar la descripción con «usar solo cuando el usuario lo pida expresamente», que es una guía blanda.

Cómo decide Claude

Insistimos: antes de usar una skill, Claude solo conoce su nombre y su descripción. Por eso la descripción decide si se activa; lo demás se carga después, si procede.

Una buena descripción dice
  • Qué hace, con una redacción directa: sin «Te ayudo a…» ni «Puedes usarla para…».
  • Cuándo se usa, con frases reales de petición (sus triggers, «disparadores»).
  • Cuándo no se usa.
  • Es breve: unos 200 caracteres (criterio de concisión de este módulo, no un límite técnico).

Si preguntan «¿200 o 1024?». El máximo técnico documentado es 1024; el seminario propone unos 200 como criterio de concisión, no como límite de Claude. Un artículo del Centro de ayuda indica 200 como máximo (botón «+»).

Cuándo se considera un fallo

La skill falla si el resultado cambia de una vez a otra: unas veces entrega tres cifras y otras ocho, o cambian el orden y la extensión.

La pregunta

¿Qué no debe hacer nunca y qué hace cuando no sabe algo?

Cómo se escribe
  1. Formúlalo como «que no invente ni añada lo que no debe» y concreta qué es cada cosa: cifras, causas o juicios que nadie pidió.
  2. Indica qué hacer cuando falta información: preguntar al usuario o marcar lo dudoso, por ejemplo con [POR VERIFICAR].
  3. Indica qué hacer ante peticiones fuera de su tarea.
  4. Añade solo límites (restricciones explícitas sobre lo que la skill no debe hacer o hasta dónde puede llegar) que eviten un error ya observado o previsible.
Versión débil

«No te inventes cosas.»

Versión mejor · el caso

«No inventes cifras que no estén en la tabla. No afirmes causas. No valores ni ordenes a personas o revistas por su mérito.»

Cuándo se considera un fallo

La skill falla si añade cifras que no están en la tabla o si presenta una causa («crece por la política X») cuando solo debía describir.

Uso seguro · 1 de 2

Una skill puede contener código, además de instrucciones.

Qué hay en su carpeta
nombre-de-la-skill/ ├── SKILL.md instrucciones ├── scripts/ código que se ejecuta ├── references/ documentación ├── assets/ plantillas, datos… └── … cualquier otro archivo

Es la estructura de la especificación abierta; solo SKILL.md es obligatorio. En Claude Code, las skills viven en ~/.claude/skills/ (personales), .claude/skills/ (proyecto) o en la carpeta skills/ de un plugin.

Qué revisar con más atención
  • Lo que ejecuta comandos o programas.
  • Lo que modifica o borra archivos.
  • Lo que se conecta a servicios externos: llamadas de red, URL, envío de datos.
  • Lo que descarga contenido de Internet.
  • En Claude Code, el campo allowed-tools: se aplica al invocar la skill aunque el repositorio no sea de confianza.
Antes de usarla
  1. Conviene comprobar su procedencia: creada por el propio usuario o procedente de una fuente de confianza.
  2. Conviene leer todos los archivos, no solo SKILL.md: también scripts, imágenes y recursos.
  3. Si no se entiende lo que hace un script, no se debe usar la skill.
  4. Conviene probarla primero sin datos personales ni confidenciales.

Skills en cuatro frases

  1. Una skill es una carpeta con un archivo de instrucciones (SKILL.md) que Claude carga solo cuando tu petición encaja con su descripción.
  2. Sirve para tareas que repites con el mismo criterio. Para lo puntual basta un prompt.
  3. La descripción decide si se usa; las instrucciones deciden si sirve. Solo lo sabrás probándola.
  4. No garantiza resultados idénticos ni correctos: se prueba con peticiones distintas y se revisa siempre.

Cómo conducir cada bloque

  1. Lee la idea clave de la diapositiva con tus palabras: está en el título.
  2. Enseña el ejemplo del caso. No hace falta abrir ningún botón de ampliar.
  3. Lanza el ejercicio y circula por la sala.
  4. Fíjate en dos señales: descripciones vagas («ayuda con…») y requisitos que la persona no ha pedido.

Lo que no necesitas dominar

YAML, Markdown, scripts, API o MCP. Si alguien pregunta, están en los botones de ampliar y en el glosario. Tampoco hace falta dominar la bibliometría: el caso solo usa un indicador, los documentos por año.

Antes de la sesión

  • Abre Claude y comprueba si aparece la sección Skills en tu cuenta.
  • Opcional: instala la skill de la demostración (botón «Copiar SKILL.md» de la diapositiva «La skill escrita») para ejecutarla en directo.
  • Abre los enlaces de la diapositiva de fuentes: menús y planes cambian.

Si te preguntan…

¿En qué se diferencia de un Proyecto o de las instrucciones personalizadas?

Las instrucciones personalizadas se aplican de forma general a todas tus conversaciones. Un Proyecto aporta conocimiento de fondo que está siempre cargado en sus chats. Una skill es un procedimiento para una tarea concreta y solo se carga cuando la tarea encaja. (Centro de ayuda, «What are Skills?»).

¿Necesito saber programar?

No. La skill de hoy es solo un archivo de texto. Las skills pueden incluir código, pero es opcional.

¿Puede Claude calcular los indicadores por mí?

Puede equivocarse en los cálculos: por eso la skill del caso copia las cifras de la tabla y obliga a indicar cualquier cociente que calcule. Calcula los indicadores con un programa específico: la skill solo los lee. Comprueba siempre las cifras.

¿Cómo sé si Claude ha usado mi skill?

Según Claude Academy, el nombre de la skill aparece mencionado en el razonamiento de Claude mientras trabaja. Si no se activa, el Centro de ayuda sugiere pedirlo de forma explícita: «Usa mi skill…». Anótalo como hallazgo.

Mi skill no se activa

Empieza por la descripción: incluye las frases reales con las que pides la tarea. Comprueba que la skill está activada en Customize › Skills y que el ajuste «Code execution and file creation» (Settings › Capabilities) está activado. Después repite la prueba.

¿Cuántos caracteres puede tener la descripción?

Hasta 1024 según la documentación de plataforma y la especificación abierta. El seminario propone unos 200 como criterio de concisión, no como límite técnico. Un artículo del Centro de ayuda de claude.ai indica 200 como máximo, de modo que ese criterio evita además cualquier rechazo al subir la skill (botón «+» de la diapositiva «Revisa el borrador e instálalo»).

¿Qué plan necesito?

Las páginas oficiales no coinciden: unas incluyen el plan gratuito y otras solo los de pago. Además, el ajuste «Code execution and file creation» debe estar activado (Settings › Capabilities; en Team y Enterprise, lo gestiona el propietario). Lo más fiable es comprobar si aparece Skills en tu cuenta; si no, ruta B.

¿Puedo compartir mi skill con compañeros?

Las fuentes no coinciden: la documentación de plataforma indica que las skills subidas a claude.ai son individuales; el Centro de ayuda describe opciones de compartir en planes Team y Enterprise. Comprueba tu plan y, antes de compartirla, pruébala y revísala como software.

¿Es segura?

La documentación recomienda usar solo skills creadas por ti o de fuentes de confianza y revisar todos sus archivos, scripts incluidos (dos últimas diapositivas). Y no pegar datos confidenciales ni de proyectos inéditos en herramientas no autorizadas por la universidad.

¿Puedo impedir que Claude use una skill por su cuenta?

Depende del producto. En Claude.ai puedes desactivar la skill o pedirla por su nombre; en Claude Code, disable-model-invocation: true deja su uso solo en tus manos. Ver «¿Quién decide cuándo se usa una skill?».

¿Da siempre el mismo resultado?

No. Puede variar entre ejecuciones. Por eso se prueba con peticiones distintas y tú revisas siempre el resultado.

¿Puedo usarla en otra herramienta que no sea Claude?

Las skills de esta sesión son de Claude. Existe una especificación abierta del formato, pero que otra herramienta la lea depende de esa herramienta: no se da por hecho. La ruta B sirve para probar las instrucciones en cualquier asistente, aunque entonces no es una skill instalada.

¿Cuánto debe medir un SKILL.md?

Poco. La documentación recomienda mantener el cuerpo por debajo de 500 líneas; el del ejemplo tiene unas treinta.

¿Puedo pedirle a Claude que escriba la skill entera?

Sí: la documentación oficial describe crear una skill conversando con Claude.

¿Con qué modelo la pruebo?

La documentación recomienda probarla con los modelos con los que la vayas a usar, porque su eficacia depende del modelo.

El asistente inventa una cifra en una prueba

Es justo lo que buscan las pruebas. Anótalo como fallo y refuerza el límite correspondiente en el apartado «Qué no debe hacer».

El archivo SKILL.md por dentro

Estructura

Una skill es una carpeta con el nombre de la skill. Dentro, como mínimo, un archivo SKILL.md:

---
name: lectura-indicadores-bibliometricos
description: Redacta la lectura de una tabla…
---
# Lectura de una tabla de indicadores
## Tarea
## Cuándo se usa
## Qué necesita
## Qué hace
## Qué entrega
## Qué no debe hacer

Carpetas opcionales

references/ (documentos de consulta), scripts/ (código que se ejecuta) y assets/ (plantillas); cabe cualquier otro archivo. La documentación recomienda mantener el cuerpo de SKILL.md por debajo de 500 líneas.

Las instrucciones (formato Markdown)

Texto con marcas sencillas: # título, ## subtítulo, 1. lista numerada, - viñeta.

La cabecera (formato YAML)

Pares «campo: valor» entre dos líneas de tres guiones. Solo name y description son obligatorios.

  • name: hasta 64 caracteres; solo minúsculas, números y guiones; sin etiquetas XML; sin las palabras «claude» ni «anthropic». La especificación abierta añade: no empezar ni acabar con guion, no repetirlo seguido y coincidir con el nombre de la carpeta.
  • description: no vacía, hasta 1024 caracteres y sin etiquetas XML. Debe decir qué hace la skill y cuándo se usa. Como se inserta en el prompt de sistema, la guía oficial recomienda la tercera persona: describir la skill sin dirigirse al usuario ni hablar en primera persona.
    RedacciónEjemplo (skill de indicadores)Motivo
    Correcta«Redacta la lectura de una tabla de indicadores bibliométricos… Usar al pedir interpretar una tabla.»Dice qué hace y cuándo se usa.
    Incorrecta«Te ayudo a interpretar tus tablas bibliométricas.»Primera persona; se dirige al usuario.
    Incorrecta«Puedes usarla para interpretar tablas.»Segunda persona.

 DOCUMENTACIÓN OFICIAL CRITERIO DIDÁCTICO

Longitud de la description: máximo técnico y criterio de concisión

  • Máximo técnico: 1024 caracteres. Lo indican la documentación de plataforma y la especificación abierta: la description no puede estar vacía ni contener etiquetas XML, y debe decir qué hace la skill y cuándo usarla.
  • Criterio de este seminario: unos 200 caracteres. No es un límite de Claude, sino una pauta de concisión: una descripción breve obliga a decidir qué hace la skill, cuándo se usa y cuándo no, y ocupa poco contexto, porque el nombre y la descripción de todas las skills instaladas se cargan siempre.

Claude permite hasta 1024 caracteres, pero aquí se propone aproximadamente 200 como criterio de concisión, no como límite técnico.

Nota sobre las fuentes: un artículo del Centro de ayuda de claude.ai («How to create custom skills») indica 200 caracteres como máximo para este campo. Las fuentes no coinciden; ceñirse a unos 200 evita, en cualquier caso, un posible rechazo al subir la skill.

Qué pueden contener references/ y assets/

Junto a SKILL.md, la especificación abierta define tres carpetas opcionales: scripts/ (código), references/ (documentación) y assets/ (plantillas y otros recursos). Son convenciones de organización, no obligaciones: la skill de la sesión funciona solo con SKILL.md. Sirven para sacar del archivo principal el material de detalle, que Claude abre únicamente si las instrucciones lo indican.

references/ · material para consultar

Documentos de texto que Claude lee cuando los necesita: guías, criterios, glosarios o normas. Cada archivo se carga a demanda, por lo que conviene que sea corto y trate un solo tema.

  • indicadores-y-su-lectura.md: qué mide cada indicador (documentos, citas, revistas) y cómo se lee.
  • limites-de-las-bases.md: por qué dos bases de datos dan cifras distintas (cobertura, fecha de descarga).
  • redaccion-prudente.md: verbos descriptivos permitidos y verbos causales que se evitan.

Se enlaza desde SKILL.md: «Si la tabla incluye citas, consulta references/indicadores-y-su-lectura.md».

assets/ · recursos para usar en el resultado

Recursos estáticos que la skill utiliza o reproduce en lo que produce: plantillas, imágenes y archivos de datos. Dan a la skill un modelo fijo de resultado en lugar de describirlo con palabras cada vez.

  • plantilla-lectura.md: los tres apartados («Qué muestra», «Cifras clave», «Límites») y la línea «Cifras comprobadas con la tabla».
  • ejemplo-produccion-anual.md: la lectura ya resuelta de una tabla de producción anual, como modelo del resultado esperado.

Se enlaza desde SKILL.md: «Entrega la lectura con el formato de assets/plantilla-lectura.md».

lectura-indicadores-bibliometricos/ ├── SKILL.md ├── references/ │ ├── indicadores-y-su-lectura.md │ └── limites-de-las-bases.md └── assets/ ├── plantilla-lectura.md └── ejemplo-produccion-anual.md

Regla práctica. Si es texto que Claude debe leer para decidir o redactar mejor, va en references/. Si es material que la skill copia, rellena o entrega tal cual, va en assets/. Si hiciera falta código (por ejemplo, un script que compruebe que cada cifra de la lectura figura en la tabla), iría en scripts/.

Seguridad. En una skill ajena se revisan también estos archivos, no solo SKILL.md.

Estos archivos son ejemplos posibles: la skill de la demostración solo tiene SKILL.md. Un artículo del Centro de ayuda de claude.ai menciona una carpeta resources/; lo decisivo es que SKILL.md indique qué contiene cada archivo y cuándo abrirlo. De una instrucción genérica a pasos comprobables

Instrucción poco útil

«Comenta la tabla.»

No dice qué se comenta, con qué criterio ni qué debe obtenerse. No hay modo de comprobar si está bien hecho, y cada ejecución puede dar un resultado distinto: un resumen, una valoración o una explicación de causas.

Pasos operativos y comprobables
Paso (una acción)Cómo se comprueba
1. Comprobar qué mide cada columna y en qué unidad.La lectura nombra la unidad de cada cifra (documentos, citas, porcentaje).
2. Elegir como máximo tres cifras clave y copiarlas de la tabla.Hay exactamente tres filas y cada valor figura en la tabla.
3. Describir lo que muestran con verbos descriptivos.No aparecen verbos causales («debido a», «gracias a»).
4. Comprobar si el último año está incompleto.Si la descarga es anterior al fin del año, aparece el aviso y ese año no se compara.
5. Cerrar con un límite y comprobar las cifras.Aparece «Límites» y la línea «Cifras comprobadas con la tabla: 3 de 3».

Cada paso es una acción (comprobar, elegir, describir, cerrar) con un resultado que se puede verificar en la respuesta, y el último paso es una comprobación. Es una versión ampliada de los cinco pasos del SKILL.md de la demostración.

La guía oficial de buenas prácticas recomienda pasos claros con verificación; «entre tres y siete pasos» es una orientación de este módulo. Skill authoring best practices.

Límites: qué son y cuáles conviene escribir

Un límite es una restricción explícita sobre lo que la skill no debe hacer o sobre hasta dónde puede llegar. Se escribe en el apartado «Qué no debe hacer» y puede ser una prohibición («no afirmar causas») o un tope («máximo tres cifras»). La idea no es llenar la skill de prohibiciones arbitrarias, sino escribir solo los límites que evitan un error ya observado o previsible.

Límite en lectura-indicadores-bibliometricosError que evita
«No inventes cifras que no estén en la tabla.»Una lectura con números que nadie puede comprobar.
«No afirmes causas: la tabla describe, no explica.»Frases como «crece por la política X», que la tabla no puede sostener.
«No valores ni ordenes a personas o revistas por su mérito.»Convertir un recuento de citas o de documentos en un juicio de calidad.
«Elige como máximo tres cifras clave.»Lecturas que repiten toda la tabla en lugar de destacar lo esencial.
«No compares el último año con los años completos si está incompleto.»Un falso descenso, porque a la descarga le faltaban meses de publicaciones.
Límites arbitrarios, que conviene evitar

«No uses nunca la palabra “tendencia”» o «Responde siempre con exactamente 137 palabras», sin ningún error real detrás, alargan la skill sin mejorarla y pueden chocar con otras instrucciones. Prueba rápida: ¿qué error concreto evita este límite? Si no puede responderse, sobra.

La guía oficial de buenas prácticas pide instrucciones concisas: cada frase debe justificar el espacio que ocupa en el contexto. Skill authoring best practices. La regla de los límites ligados a un error es una decisión didáctica de este módulo.

 DECISIÓN DIDÁCTICA

Cómo dar y recibir la revisión

Quien revisa

  1. Empieza por dos cosas que funcionan, con la frase que lo demuestra.
  2. Señala como máximo tres cambios, cada uno con la frase del archivo o de las pruebas que lo justifica.
  3. Pregunta antes de proponer: «¿Qué debería hacer aquí la skill?». No reescribas la skill de la otra persona.

Quien es autora

  1. Escucha sin defender: si alguien no entiende una instrucción, la instrucción es mejorable.
  2. Decide qué dos cambios haces primero.
  3. Si no compartes una observación, anótala con la razón.

Pregunta para cerrar: «Si yo no estuviera, ¿podría otra persona usar esta skill sin preguntarme nada?»

Instalar la skill (ruta A) y comprobar que se usa

Pasos

  1. Crea una carpeta con el mismo nombre que la skill (el campo name) y guarda dentro SKILL.md.
  2. Comprime la carpeta en un archivo ZIP. La carpeta debe ser la raíz del ZIP.
  3. En Claude: Customize › Skills, pulsa «+», «+ Create skill» y «Upload a skill», y sube el ZIP.
  4. Comprueba que el interruptor de la skill está activado.
  5. Prueba en un chat nuevo pidiendo la tarea con tus palabras, sin nombrar la skill.

Alternativa

Abre un chat nuevo, di que quieres crear una skill y responde a las preguntas de Claude: genera el SKILL.md y lo guardas (Claude Academy).

Si falla la subida

  • El nombre de la carpeta no coincide con el nombre de la skill.
  • Falta el archivo SKILL.md.
  • Caracteres no válidos en el nombre o la descripción.
  • El ZIP contiene la carpeta anidada, o es demasiado grande.

Cómo saber que Claude la usó

El nombre de la skill aparece mencionado en el razonamiento de Claude mientras trabaja (Claude Academy). Si no se activa, pídelo de forma explícita: «Usa mi skill…» (Centro de ayuda). Anota lo ocurrido: es un hallazgo, no un error tuyo.

Si los ajustes salen en gris

Puede que el ajuste «Code execution and file creation» esté desactivado por la organización. En Team y Enterprise, un propietario puede desactivar la creación de skills.
